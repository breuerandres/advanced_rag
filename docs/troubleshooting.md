# Troubleshooting

Operational notes for local development issues that are likely to recur.

## Caddy Local HTTPS Certificate Warning

### Symptom

The browser shows a certificate warning for:

- `https://manage.localhost`
- `https://chat.localhost`
- `https://docs.localhost`

Running `caddy trust` on Windows does not fix the warning.

### Cause

The project Caddy instance runs in Docker Compose, using the `caddy:2-alpine` image from `infra/compose/compose.yaml`.

The Compose service mounts:

- `infra/compose/Caddyfile` at `/etc/caddy/Caddyfile`
- the Docker volume `caddy-data` at `/data`
- the Docker volume `caddy-config` at `/config`

The local `Caddyfile` uses `tls internal`, so Caddy generates a local internal certificate authority inside the container data volume. Running `caddy trust` on the Windows host trusts the CA for a different host-installed Caddy instance, not the CA generated by the Docker Compose Caddy container.

The browser needs to trust the root certificate generated by the Compose Caddy container.

### Fix

Start the Compose Caddy service:

```powershell
docker compose --env-file infra\compose\.env.example -f infra\compose\compose.yaml -f infra\compose\compose.override.yaml up -d caddy
```

Copy the container-generated root CA certificate to the workspace:

```powershell
docker compose --env-file infra\compose\.env.example -f infra\compose\compose.yaml -f infra\compose\compose.override.yaml cp caddy:/data/caddy/pki/authorities/local/root.crt .\caddy-local-root.crt
```

Import it into the current user's trusted root store:

```powershell
Import-Certificate -FilePath .\caddy-local-root.crt -CertStoreLocation Cert:\CurrentUser\Root
```

If importing into the machine-wide root store, run PowerShell as administrator:

```powershell
Import-Certificate -FilePath .\caddy-local-root.crt -CertStoreLocation Cert:\LocalMachine\Root
```

Close and reopen the browser after importing the certificate.

### Firefox Note

Firefox may use its own certificate store depending on local settings. If the warning remains in Firefox after importing the certificate into Windows, either enable Firefox's Windows certificate store integration or import `caddy-local-root.crt` directly into Firefox certificate authorities.

### Verification

Check that Caddy is running:

```powershell
docker compose --env-file infra\compose\.env.example -f infra\compose\compose.yaml -f infra\compose\compose.override.yaml ps caddy
```

Check Caddy logs:

```powershell
docker compose --env-file infra\compose\.env.example -f infra\compose\compose.yaml -f infra\compose\compose.override.yaml logs caddy
```

Open:

- `https://manage.localhost`
- `https://chat.localhost`
- `https://docs.localhost`

### When This Needs To Be Repeated

The trusted certificate remains valid while the Docker volume `caddy-data` is preserved. If `caddy-data` is deleted, for example through a Docker volume prune or explicit volume removal, Caddy generates a new internal CA and the root certificate import must be repeated.
